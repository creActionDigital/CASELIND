# Registre des décisions (ADR)

| # | Date | Décision | Raisons | Alternatives écartées | Réversibilité |
|---|---|---|---|---|---|
| ADR-001 | 2026-11-01 | Monorepo **npm workspaces** | pnpm absent ; npm 11 présent ; aucune dépendance d'outil supplémentaire | pnpm, Nx, Turborepo (ajoutables plus tard) | Facile |
| ADR-002 | 2026-11-01 | API **NestJS 12 en ESM** | Imposé par le CDC §28 ; NestJS 12 est publié en ESM pur | CommonJS (incompatible avec v12) | — |
| ADR-003 | 2026-11-01 | **Drizzle ORM** + migrations **SQL écrites à la main** | SQL explicite (CHECK, citext, triggers append-only, PostGIS plus tard), pas de binaire de moteur, bon typage | Prisma (moteur binaire, contrôle SQL moindre), TypeORM (typage plus faible), drizzle-kit (génération de migrations : retiré pour garder la main sur le SQL) | Moyenne |
| ADR-004 | 2026-11-01 | **PostgreSQL embarqué** (`embedded-postgres`) en dev et en test | Ni Docker ni PostgreSQL installés ; tests contre une vraie base plutôt que des mocks | SQLite (divergences SQL), PGlite (WASM, extensions limitées) | Facile : `DATABASE_URL` / `TEST_DATABASE_ADMIN_URL` pointent vers n'importe quel PostgreSQL |
| ADR-005 | 2026-11-01 | **Vitest + SWC** pour les tests | Le backend est en ESM ; Jest y reste fragile ; SWC émet les métadonnées de décorateurs | Jest + ts-jest | Facile |
| ADR-006 | 2026-11-01 | **Zod** dans `packages/contracts`, partagé api/mobile/web | Un seul schéma pour valider côté serveur et typer les clients | class-validator (non partageable avec React Native) | Moyenne |
| ADR-007 | 2026-11-01 | JWT court + **refresh opaque à rotation**, sessions vérifiées en base à chaque requête | Révocation immédiate (CDC §4 : déconnexion à distance) ; détection de vol de jeton | JWT seul (révocation impossible), sessions cookie (moins adaptées au mobile) | Moyenne |
| ADR-008 | 2026-11-01 | OTP derrière un port `OtpSender` ; adaptateur **console** en dev, refusé en production | Aucun fournisseur SMS contracté ; ne pas activer de service payant sans accord (CDC §40.9) | Twilio, Africa's Talking, etc. : **décision du propriétaire** | Facile (nouvel adaptateur) |
| ADR-009 | 2026-11-01 | Cartographie WeChat à partir de **sources publiques** ; REA non utilisé | REA n'a ni serveur MCP ni CLI ici. Surtout, il sert à décompiler des artefacts livrés : appliqué à WeChat, cela poserait un problème de licence et de propriété intellectuelle. | Décompilation de l'APK WeChat (rejetée : illégal / hors cadre) | — |
| ADR-010 | 2026-11-01 | Pas de Redis au lot 1 | Ne pas ajouter d'infrastructure sans besoin mesuré (CDC §28) ; throttling en mémoire par instance | Redis dès le départ | Facile : stockage du throttler et cache de sessions à basculer sur Redis en multi-instance |
| ADR-011 | 2026-11-01 | **OpenAPI 3.1 généré depuis les contrats Zod** (`z.toJSONSchema`, `io: 'input'` pour les entrées et `'output'` pour les sorties) à partir d'un **registre déclaratif des routes** (`apps/api/src/openapi/registry.ts`), servi par `GET /v1/openapi.json`. Un test d'exhaustivité compare, dans les deux sens, les routes réellement montées et le registre | Une seule source de vérité (les schémas Zod partagés) ; aucune dépendance supplémentaire ; une route oubliée dans le registre fait échouer les tests | `@nestjs/swagger` (exige TypeScript 5/6 en peer alors que le projet est en TS 7, et repose sur class-validator, que nous n'utilisons pas, ADR-006) | Facile : le registre peut alimenter un autre générateur |
| ADR-012 | 2026-11-01 | **Suppression de compte avec délai de grâce** (`ACCOUNT_DELETION_GRACE_DAYS`, 30 j par défaut). La demande exige le mot de passe, révoque toutes les sessions et masque le profil. Une connexion réussie pendant le délai **annule** la demande. Après le délai, la connexion est refusée (403 `account_suspended`), même avant la purge. La purge **anonymise** la ligne (identifiants libérés, mot de passe inutilisable, sessions, OTP et blocages supprimés) et conserve l'audit append-only, qui ne référence plus que l'id | Comportement courant, réversible pour l'utilisateur ; droit à l'effacement (CDC §4, §29) sans casser l'intégrité référentielle ni le journal d'audit | Suppression physique immédiate (irréversible, casse l'audit) ; annulation par une route dédiée seulement (plus de friction) | Moyenne : les règles de conservation par pays restent à définir |
| ADR-013 | 2026-11-01 | **Flags réglementés : confirmation explicite.** Activer un flag `regulated`, ou élargir sa portée (pays, rôles) tant qu'il est actif, exige `confirmRegulated: true` (sinon 409). La lecture, la décision, l'écriture et l'audit se font dans **une transaction, ligne verrouillée** (`SELECT … FOR UPDATE`) | Les modules réglementés (paiements, paris, santé) ne doivent jamais s'ouvrir par erreur (CDC §21, §26). La revue a montré qu'une décision prise hors verrou laissait passer un élargissement non confirmé entre deux requêtes concurrentes (TOCTOU) ; un test de concurrence le prouve | Contrôle applicatif sans verrou (TOCTOU) ; validation à deux personnes (prévue plus tard avec le back-office) | Facile |
